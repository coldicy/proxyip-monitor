1 概述

Proxy Monitor 用于长期监控、筛选并同步 Cloudflare 反代 IP / ProxyIP：周期性真实 HTTPS 探测，计算 TCP/TLS/HTTP 回源延迟，统计成功率与达标率；节点首次在线时执行一次性下载测速；满足优质窗口（含速度下限与连续在线下限）的节点可上传 GitHub。

  • 节点来源：纯 IP / 域名 / URL 列表源。
  • 优质 = 样本充足 & 成功率 ≥ 阈值 & 达标率 ≥ 阈值 & 测速 ≥ 速度下限 & 连续在线 ≥ 下限（若设置）。
  • 每次失败原因随样本持久化，任意一次离线可回溯。
  • 离线节点的地区/数据中心/出口IP 用最近一次成功样本补齐。

2 快速开始

  1. ⚙️ 设置 → 填写 ip.txt。
  2. 需要真实回源验证时添加自定义源站探针。
  3. 设置延迟上限、速度下限、成功率/达标率阈值。
  4. 💾 保存并重载节点，等待检测与一次性测速完成。
  5. 使用筛选/复制/上传。

优质需要样本充足：窗口为 N 时至少 N 次样本后才判定；测速在首次在线时自动完成。

3 节点列表格式

在 ⚙️ 设置的 节点列表 ip.txt 中，每行可以写一个节点来源：

# 这是注释，不会被解析
1.2.3.4
1.2.3.4:8443
example.com
example.com:443
https://example.com/proxyip-list.txt
  • 不写端口时，默认使用 443。
  • 支持 # 注释；IPv6 不会进入主列表。

解析与保留机制（重要）

  • 动态解析：每一轮检测开始前，系统都会重新读取该列表。对域名重新做 DNS 解析，对 URL 列表源重新拉取最新内容。
  • 只增不减：如果域名解析出了新 IP，或列表源增加了新 IP，它们会自动加入监控；如果旧 IP 在最新的解析结果中消失了，它依然会保留在监控列表中继续被检测。
  • 如何彻底移除：未被解析到的旧 IP，只有在“长期离线触发自动清理”或“在面板中手动删除”时，才会真正从系统中移除并进入屏蔽名单。

4 核心指标

指标含义
平均总延迟窗口内在线样本总延迟平均 = 官方+自定义探针平均（TCP/TLS/HTTP 同理）。
成功率窗口内在线次数 / 窗口大小。
达标率窗口内“在线且总延迟≤上限”次数 / 窗口；上限 0 时等同成功率。
下载速度一次性测速结果 MB/s（见 5）。
连续在线自最近一次失败后持续在线的时长（失败即清零，持久化不丢）；表格实时显示，筛选支持按小时比较。
优质样本充足 & 成功率≥阈值 & 达标率≥阈值 & 速度≥下限 & 连续在线≥下限（若设置，见 8）。

5 一次性测速

  • 原理：--resolve 走被测 IP 下载测速 URL（默认 speed.cloudflare.com 20MB 上限），--max-time 10s 时间上限；速度 = 已下载字节 / 耗时，超时截断也得到有效平均速度。
  • 两阶段执行：延迟阶段（高并发小请求）结束后，再对“本轮在线且需要测速”的节点跑测速阶段。
  • 独立低并发（默认 1，可配 1-3）+ 每周期配额（默认 20），避免本地带宽争抢；配额外的顺延后续周期。
  • 只测一次：成功记录永不自动复测；失败记录仅在本轮在线且间隔 >10 分钟时重试；离线节点完全不测，不浪费性能。
  • 结果持久化在节点上，重启不丢、不重复测。
  • 优质门槛：速度下限 >0 时，测速不达标或未测速成功的节点不评为优质/不上传。
  • 手动复测：行内 ⚡ 按钮（用户主动，不受“不复测”限制）。
  • 测速真实消耗节点带宽（单节点封顶 20MB/10s）。测速结果本质是 min(节点能力, 本地带宽÷并发)，速度下限请参照监控机本地带宽设置。

6 探针分工

官方探针

  • 默认 cloudflare trace，检测反代能力并读取 colo/loc/出口IP；必须返回 CF 内容，且回显本次随机 UA（uag=…）防伪造。

自定义源站探针

  • 验证真实回源；全部成功该次才在线；失败记录精确原因（如 预期200实际502）。

7 页面操作

筛选与排序

  • 状态：全部/优质/达标/未达标/在线/离线。其中「在线」= 优质+达标+未达标（即最近一次检测通过）；「未达标」= 在线但最近一次总延迟超上限（未设上限时在线即达标）。
  • 数值筛选：总延迟 / 速度 / 达标率 / 成功率 / 连续在线 的运算符（≤ / ≥ / < / > / =）为可点击文本，点击展开切换，默认总延迟 ≤、其余 ≥；输入框留空 = 不启用该条件。连续在线单位为小时（离线节点按 0 计）。
  • 排序新增“下载速度降序”“连续在线时长降序”（离线节点按 0 小时计，降序时排在最后）。

表格

  • 节点信息：IP:端口 同行显示身份标签（CloudflareIP/ProxyIP）；下方三行依次为 ① 首次引入时间 + 来源；② 地区(国旗) + 数据中心 + 出口IP（离线时历史补齐）；③ 最近检测时间。
  • 状态徽章：优质 / 达标 / 未达标 / 离线，语义互斥。
  • 下载速度列：绿=达标或未设下限；红=低于下限；-=未测速/失败（悬浮看原因与时间）。
  • 连续在线列：显示自最近一次失败后持续在线的时长（天/小时/分），失败清零；-=当前不在线（悬浮可看连续在线起点时间）。
  • 操作：复制 / ⚡复测 / 删除。
  • 延迟柱：绿=在线达标，黄=在线超上限，红=失败；悬浮红柱看该次精确失败原因。柱数 = 优质窗口大小（上限 50）。

复制格式

IP:端口#地区 | 数据中心 | 总延迟 | TCP | TLS | HTTP | 下载速度
172.64.53.74:443#CN | NRT | 334ms | 116ms | 102ms | 116ms | 14.80MB/s

📋 复制筛选节点 = 当前筛选+排序结果；只复制优质先选状态=优质或勾选只看优质。

8 设置说明

配置项说明
启用节点测速关闭后不自动测速，且优质判定忽略速度下限。
优质下载速度下限 (MB/s)0=不限；>0 时测速达标才计入优质/上传。
优质最低连续在线 (小时)0=不限；>0 时节点需连续在线满该小时数才评优质/上传；失败清零后重新累积。
测速并发 (1-3)独立于延迟并发，默认 1，避免本地带宽争抢。
每周期测速配额默认 20；新节点多时顺延后续周期消化。
测速超时 (秒)单节点时间上限，默认 10。
测速 URL默认 20MB 下载端点；可调 bytes 改变体量。
优质判定窗口 (1-50)后端每节点仅保留窗口大小样本，前端同步限制 1-50。
达标率阈值 / 成功率阈值达标率不能高于成功率，否则后端会自动将其拉平。
GitHub Token加密存储；输入框留空 = 保持当前 Token 不变（见 9）。
其余间隔/超时/并发/延迟上限/探针 同前。

底部两个保存按钮的区别

按钮作用范围适用场景
💾 保存配置仅保存上方的 运行参数（间隔、阈值、测速、GitHub等）。只想调整运行参数，不修改下方 ip.txt 节点列表时使用。
💾 保存并重载节点保存 运行参数 + 保存下方 节点列表，并立刻触发一次节点发现。当你新增、修改或删除了下方 ip.txt 中的 IP/域名/URL 时，必须点此按钮才能让新节点立刻生效。

9 GitHub 同步

上传 前缀_all.txt 与按地区拆分文件；行格式同复制格式（含数据中心与下载速度，缺失时为 Unknown / ?MB/s）；支持手动/变化自动/定时上传。部分文件上传失败时不会标记为已同步，下一轮会自动重试。

Token 安全

  • 真实 Token 仅存于 dataDir/github.secret（文件权限 600）或环境变量，永不明文写入 config.json。
  • 接口只返回打码值（如 abcd****wxyz）；设置页输入框显示“留空=保持不变”，输入新值才会更新。
  • 旧版本 config.json 中的明文 Token 会在首次启动时自动迁移到加密存储并从 config.json 删除。
  • 探针 URL / 自定义探针 URL 在保存时会做安全消毒，防止命令注入。

10 删除与屏蔽

手动删除/自动清理均进屏蔽记录；可在设置面板中单独或批量解除屏蔽；清空记录 = 解除全部屏蔽。

11 常见问题

延迟好却不是优质？

  • 样本不足/成功率/达标率不达标；或速度下限未达标/未测速成功；或连续在线未满「优质最低连续在线」（失败清零后需重新累积）。

速度列显示 - ？

  • 尚未在线过（未触发测速），或测速失败（悬浮看原因；在线时 10 分钟自动重试，也可 ⚡ 手动复测）。

会不会把节点测死？

  • 不会：成功只测一次；失败重试间隔 10 分钟且仅在线时；离线完全不测；并发默认 1；单节点封顶 20MB/10s。

离线原因？

  • 悬浮红柱或离线徽章查看（随样本持久化）。

Token 会泄露吗？

  • 不会：接口只返回打码值；页面永远看不到完整 Token。

13 最佳实践

  • 速度下限从低到高调整（1→5→10 MB/s）观察优质数量。
  • 间隔 60-300s；窗口 10-50；成功率 0.9-1；达标率 0.8-1。
  • 真实业务务必配置自定义源站探针。
  • 测速并发保持 1-2，监控机带宽小时尤其注意。
  • Token 建议用最小权限（仅仓库 contents 读写），并定期轮换。
